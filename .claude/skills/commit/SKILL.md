# コミット規約(ec-learning)

このリポジトリは公開前提の学習プロジェクト。コミット履歴自体が「学習の記録」として読まれることを意識する。

## 粒度

- **1コミット = 1つの論理的な作業単位**。フェーズのステップ単位(A-1, A-2, ...)が目安
- 複数ステップ分が未コミットで溜まっていたら、ファイルをグループ分けして複数コミットに割る
- 生成物(例: `db/schema.sql` は pg_dump の出力)は、それを生んだ変更と同じコミットに入れる
- 計測結果(`docs/measurements/`)は、それを取得した仕組み・変更と同じコミットに入れる

## メッセージ形式

```
<type>: <日本語の要約>

(任意の本文: なぜその変更をしたか。設計判断があればトレードオフを1〜2行で。
 対応するステップ(例: フェーズA A-3)や ADR 番号があれば参照する)
```

- type: `feat` / `fix` / `docs` / `chore` / `refactor` / `perf` / `test`
- 要約は50字以内目安。「何をしたか」ではなく「何ができるようになったか」を優先
- 学習プロジェクトなので、本文に「この変更で観察できるようになったこと」を書く価値が高い

## 手順

1. `git status` と `git diff` で全変更を把握する(未追跡ファイルを含む)
2. 論理単位にグループ分けし、`git add <対象ファイル>` → `git commit` を繰り返す
3. gitignore 対象(`data/*.csv`, `node_modules/`)が誤って追跡されていないか確認する
4. 最後に `git log --oneline` で結果を提示する

## 禁止・注意

- `git add -A` での無差別ステージは、未コミット変更が単一の論理単位のときのみ可
- force push・履歴書き換えはユーザーが明示的に求めた場合のみ
- コミットするのはユーザーに頼まれたとき、または提案して合意を得たときのみ
