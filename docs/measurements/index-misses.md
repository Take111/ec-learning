# 効かないケース集: インデックスが役に立たない条件の実測

一時インデックス + ROLLBACK で実施(スキーマ変更なし)。2026-08-21。

| ケース | プラン | Buffers | 教訓 |
|---|---|---|---|
| `ship_to_prefecture='東京都'`(11%・相関0.05) | Bitmap だが全体の98%を触る | 5,408 | 「使われた」≠「効いた」。強制Seq Scan(5,450p)と同等、並列の分Seqが速い |
| 同 `'鳥取県'`(0.4%) | Bitmap | 1,056 | 同じインデックスでも値の選択率で価値が5倍違う |
| `name LIKE '%カメラ%'` | Seq Scan | — | 先頭不定はB-treeの起点が作れない(本命は pg_trgm+GIN) |
| `name LIKE 'ノルディア%'` + 通常btree | **Seq Scan** | — | 照合順序 en_US.utf8 ではバイト順≠索引順で前方一致も不可 |
| 同 + text_pattern_ops | Bitmap | — | バイト順の演算子クラスで前方一致が復活 |
| `user_id::text = '78872'` | Seq Scan | 5,526(正:24) | 列の加工でインデックスも統計も引けなくなる(推定625 vs 実2,936) |

## 統一原理

インデックスも統計も「素の列(+演算子クラス+照合)をキーにした表」。
関数・キャスト・非互換照合で列を加工した瞬間、どの表からも引けない。

## 使った診断道具

- `SET LOCAL enable_bitmapscan = off` — プラン強制はトランザクション内・診断限定で
