# ADR 006: ページネーションはカーソル方式を正とする

- ステータス: 採用
- 日付: 2026-08-21

## 背景

一覧APIのページ送り方式。OFFSET が最も素朴だが、深いページで劣化することが
知られている。実測で選択肢を比較した(docs/measurements/pagination.md)。

## 選択肢と実測

| 方式 | 深さ100,000での実測 | 特性 |
|---|---|---|
| OFFSET(索引なし) | 5,450p + external merge Disk 4.5MB | 全ページが全件ソートの料金 |
| OFFSET(索引あり) | 2,198p | O(深さ)。索引は定数を下げるだけ |
| カーソル(keyset) | 5p / 0.06ms | O(1)。ただし任意ページへのジャンプ不可 |

## 決定

カーソル方式 `WHERE (ordered_at, id) < (最後に見た値) ORDER BY ... LIMIT n` を正とする。
ソートキーは必ず「ORDER BY列 + ユニーク列(id)」で全順序にする
(タイブレークなしはページ境界で行の重複・欠落が起きうる)。

## 根拠

- 行値比較が丸ごと Index Cond に入り、複合インデックス (ordered_at, id) の
  並びと同型 — 木を1回降りるだけで深さに依存しない
- 主用途(注文履歴・無限スクロール)は前後移動のみで、ジャンプ不要

## 帰結

- フェーズBの一覧APIは next_cursor(opaque なトークン)を返す設計にする
- ページ番号UIが必要な画面が出たら、その画面に限り OFFSET を許容して
  最大深さを制限する(例: 100ページまで)
