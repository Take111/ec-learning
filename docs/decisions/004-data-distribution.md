# ADR 004: 生成データに現実的な偏りを入れる

- ステータス: 採用
- 日付: 2026-08-17

## 背景

fakerで100万件規模のデータを生成する。一様乱数が最も簡単だが、学習の主目的は
「プランナの見積もりと実測のズレ」「インデックスが効く/効かない条件」の観察。

## 選択肢

1. **一様乱数** — 実装が簡単。ただしプランナが常に正確に見積もれてしまい、
   実務で起きる現象(推定ズレ、効かないインデックス)がほぼ再現しない
2. **現実的な偏りを入れる** — 生成は複雑になるが、観察したい現象を仕込める

## 決定

選択肢2。入れた偏りと、それが可能にした観察:

| 偏り | 観察できたこと(実測) |
|---|---|
| 都道府県=人口比(東京11%) | 「使われたが1ページも節約しない」インデックス(index-misses.md) |
| ユーザー注文数=Zipf(上位1%が21.5%) | 同一クエリでも値によりプランが変わる(MCV、q1) |
| 商品売上=パレート | サンプリング由来の n_distinct 1/4 過小推定(q3b) |
| 注文日時=直近偏重 | 期間と行数が比例しない/ヒストグラムは偏りに強い(q2) |
| レビュー=J字(★5が48%) | HAVING avg>=4 が62%通過し絞り込みにならない(q5) |
| id を時刻順採番 | correlation 0.99999 → 選択率53%でも索引が勝つ、BRIN成立(q2) |

## 再現性の担保

- 乱数シードと「現在時刻」(ANCHOR)を両方固定。CSVはgit管理せず、
  同一シードから同一CSV(MD5一致を確認済み)を再生成できることを唯一の担保とする
- 注意: クエリ側で now() を使うと凍結データとの間で計測の再現性が失われる
  (実測時に窓の中身が日々縮む現象を確認。pagination.md 参照)

## この判断が覆る条件

- 「新商品の発売日×売上」の分析をしたくなったら、全商品を注文期間前に
  作る前提(時刻整合の簡略化)を外し、生成と注文側の商品選択を変える
