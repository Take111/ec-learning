# ADR 001: PostgreSQL 18 を採用する

- ステータス: 採用
- 日付: 2026-08-16

## 背景

学習用ECのDBを選ぶ。本番移行先は未定で外部制約がない。実務で最も普及して
いるのは16系だが、学習の主目的は「クエリ性能をEXPLAINで実測しながら学ぶ」こと。

## 選択肢

1. **PostgreSQL 16** — 実務で最多。ネットの知見がそのまま通用する
2. **PostgreSQL 17** — 無難な中間
3. **PostgreSQL 18** — 現時点の最新安定版(19はBeta)

## 決定

PostgreSQL 18。

## 根拠

- EXPLAIN で BUFFERS がデフォルト表示・`Index Searches:` 行の追加など、
  実測学習に直接効く改善がある
- skip scan(複合インデックスの先頭列スキップ)が実測できた:
  先頭列5種なら自然選択で読み1/25(docs/measurements/skip-scan.md)。
  「先頭列を指定しない複合は無用」という旧鉄則の更新を体験できた
- EOLが最も長く、古いメジャーをあえて選ぶ積極的理由がない

## 副作用・注意

- 公式Dockerイメージ18からvolumeマウント先が /var/lib/postgresql に変更
  (古い記事の compose 例をコピーするとデータ消失。docker-compose.yml に記録)

## この判断が覆る条件

- 本番移行先が決まり、そのマネージドサービスが18未対応の場合
